# SPEC — 사내 도서 대여 POC

## 목표

Claude Code 와 git worktree 로 백엔드 · 프론트엔드를 나눠 만들어, 하루 안에 「목록 → 대여 → 이미 빌린 책 거부 → 반납」 흐름이 동작하는지 확인한다.

## 성공 기준

검증은 API 는 curl(HTTP 호출), 화면은 브라우저 수동 확인으로 한다. 각 기준은 통과 · 실패 중 하나로 판정한다.

- **(a) 목록**: `GET /books` 가 HTTP 200 과 샘플 5권(제목 · 대여 상태 · 대여자)을 돌려주고, 화면에 5권이 모두 표시되면 통과. 5권이 아니거나 화면에 안 보이면 실패.
- **(b) 대여**: 대여 가능한 책에 이름을 넣어 `POST /books/:id/rent` 를 호출하면 HTTP 200 이고, 이후 목록과 화면에 「대여 중」과 대여자 이름이 표시되면 통과. 그렇지 않으면 실패.
- **(c) 핵심 규칙 거부**: 이미 대여 중인 책에 `POST /books/:id/rent` 를 다시 호출하면 HTTP 409 와 `{"error":"이미 대여 중인 책입니다"}` 를 돌려주고, 책의 상태와 대여자가 바뀌지 않으며, 화면에 같은 메시지가 표시되면 통과. 200 이 오거나 상태가 바뀌면 실패.
- **(d) 반납**: 대여 중인 책에 `POST /books/:id/return` 을 호출하면 HTTP 200 이고, 이후 목록과 화면에 「대여 가능」으로 표시되며 다시 대여하면 성공하면 통과. 그렇지 않으면 실패.

## 만들 것

- 스택: Node.js 24 · Express 5 · better-sqlite3 · React + Vite
- `server/`: API
  - 표 1개: `books` (id, 제목, 대여자 — 비어 있으면 대여 가능)
  - API 4개: `GET /books`, `POST /books/:id/rent`, `POST /books/:id/return`, `GET /health`
  - 샘플 책 5권을 서버 시작 시 넣는다
  - 핵심 규칙: 대여 중인 책을 다시 빌리면 HTTP 409 로 거부
- `client/`: 화면 1개 — 책 목록 · 대여 상태, 이름 입력, 대여 · 반납 버튼, 오류 메시지 표시
- 반납은 이름 확인 없이 누구나 할 수 있다

## 만들지 않을 것

- 로그인 · 회원 · 배포 · 결제 · 외부 API 연동
- 대여 이력, 검색, 책 추가 · 삭제 화면
- 반납자 본인 확인
- 자동 테스트 (검증은 curl 과 수동 확인)
