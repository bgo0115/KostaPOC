# 작업 목록 — 사내 도서 대여 POC

`docs/design.md` 를 바탕으로 백엔드와 프론트엔드를 나눈다. 백엔드는 `server/`, 프론트엔드는 `client/` 만 수정한다. API 명세(design.md 3절)가 두 쪽의 계약이다.

## 백엔드 (`server/`)

### 3차시 — 스캐폴딩 · DB · 목록 API

- [ ] B1. 루트 `package.json`(workspaces)과 `server/` 스캐폴딩: `app.js` · `server.js`, 3000 포트, `GET /api/health`
- [ ] B2. DB: `books` 표 만들기, `DB_PATH`(기본 `app.db`), 비어 있을 때만 샘플 5권 넣기
- [ ] B3. `GET /api/books` — 완료 기준: curl 로 200 과 5권 확인(성공 기준 a)

### 4차시 — 나머지 API

- [ ] B4. `POST /api/books/:id/rent` — 200 · 400 · 404 · 409(이미 대여 중). 완료 기준: curl 로 성공 기준 (b) · (c) 확인
- [ ] B5. `POST /api/books/:id/return` — 200 · 404 · 409. 완료 기준: curl 로 반납 후 재대여까지 성공 기준 (d) 확인

## 프론트엔드 (`client/`)

### 3차시 — 스캐폴딩 · 목록

- [ ] F1. `client/` 스캐폴딩: React + Vite, 5173 포트, `/api` 를 3000 으로 전달하는 proxy
- [ ] F2. 목록 화면: `GET /api/books` 로 책 이름 · 저자 · 대여 상태 표시. 완료 기준: 브라우저에서 5권 확인(성공 기준 a)

### 4차시 — 대여 · 반납 · 오류 안내

- [ ] F3. 이름 · 대여 기간 입력칸과 「대여」 버튼. 완료 기준: 대여 후 목록에 대여자 · 빌린 날 · 반납 예정일 표시(성공 기준 b)
- [ ] F4. 「반납」 버튼. 완료 기준: 반납 후 「대여 가능」으로 바뀌고 다시 대여됨(성공 기준 d)
- [ ] F5. 오류 안내: API 의 `error` 메시지를 화면 위쪽에 표시. 완료 기준: 대여 중인 책을 다시 빌리면 메시지 표시(성공 기준 c)
