# POC 결과 — 사내 도서 대여

## 1. 성공 기준별 결과

기준은 `docs/SPEC.md` 의 (a)~(d) 이다. 자동 테스트(`npm test`, `server/test/books.test.js`)는 API 쪽만 확인한다. 화면 표시는 이번 검증에서 직접 확인하지 않았다.

| 기준 | API (npm test) | 화면 (브라우저 수동 확인) |
|------|----------------|---------------------------|
| (a) 목록: 200 + 샘플 5권 | 통과 | 미확인 |
| (b) 대여: 200 + 대여자 표시 | 통과 | 미확인 |
| (c) 핵심 규칙 거부: 409 + 메시지, 상태 불변 | 통과 | 미확인 |
| (d) 반납: 200 + 대여 가능 복귀 + 재대여 | 통과 | 미확인 |

- `npm test`: 4개 중 4개 통과, 실패 0 (수정 전·후 모두 동일).
- SPEC 은 검증을 curl 과 수동 확인으로 정했고 자동 테스트는 만들지 않는다고 적었다. 자동 테스트는 그보다 더 확인하려고 추가한 것이다. SPEC 과 어긋나므로 정리가 필요하다.

## 3. 이번에 고친 것

- `server/server.js`: 포트가 사용 중일 때 종료 코드를 0 에서 1 로 바꿨다.
- `server/db.js`: 기본 DB 경로를 `server/app.db` 로 고정했다. 환경 변수 `DB_PATH` 는 그대로 우선한다.
- `npm test` 를 다시 실행해 4개 모두 통과했다. 포트 충돌 시 종료 코드 1 도 확인했다. 저장소 루트에서 `node server/server.js` 를 실행해도 루트에 `app.db` 가 생기지 않는다.

## 4. 판정: 조건부 적합

**이유**

- 적합한 점: SPEC 의 (a)~(d) 흐름(목록 → 대여 → 이미 빌린 책 거부 → 반납)이 API 수준에서 4개 모두 통과했다. 핵심 규칙은 `borrower IS NULL` 조건의 UPDATE 한 번으로 처리해서, 동시에 요청해도 중복 대여가 생기지 않는다.
- 조건 1: 화면 쪽 통과 여부를 확인하지 못했다. 브라우저에서 (a)~(d) 를 직접 확인해야 판정을 확정할 수 있다.
- 조건 2: 즉시 수정 2건(server #1, #2)은 모두 반영했다. 남은 것은 조건 1 뿐이다.
- 제품화 조건: 보고서 기록 10건 중 특히 이름 검증·시간대·중복 클릭 처리·오류 안내가 필요하다. 인증이 없어 반납을 누구나 할 수 있는 점은 SPEC 이 정한 범위 밖이지만, 30명 규모의 실제 운영에서는 다시 따져 봐야 한다.
- 부적합으로 보지 않는 이유: 확인된 결함은 모두 데모 흐름 밖의 예외 상황이고, 핵심 규칙은 서버가 지킨다.
